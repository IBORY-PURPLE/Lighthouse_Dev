# LightHouse 기술 설계 1쪽 요약 (사람용)

기준: `docs/TSD.md` v2(2026-11-09 승인)와 v2.1(2026-11-13, 봉사자 ③④⑤를 리서치 챗 한 화면으로 합침). 상세와 근거는 TSD 본문과 `docs/plans/2026-11-09-overnight/tsd-review.md`. TSD가 바뀌면 이 문서도 같이 고친다.

**무엇을 만드나**: 시각장애인이 음성으로 상품을 요청하면, 봉사자가 AI 조언을 받아 쇼핑몰에서 직접 찾아 결과를 보내는 모바일 웹. AI는 봉사자를 돕기만 하고, 서버와 AI는 쇼핑몰에 접속하지 않는다. 11/24 중간 시연이 목표다.

**흐름** (이용자와 봉사자는 실시간으로 대화하지 않고, 대기열과 결과함을 거쳐 만난다)
- 플로우 A, 이용자: 질문 3개(제품, 예산, 새 제품·중고)에 답 → "봉사자 매칭 요청" → 대기번호를 듣는다. 앱을 다시 열면 대기번호를 다시 듣는다.
- 플로우 B, 봉사자: 대기열에서 요청 선택(먼저 고른 한 명만 성공) → 리서치 챗(③④⑤): 질문 카드 7장(기종, 장점, 사진, 같이 고민한 제품, 고민한 이유, 혜택, 참고 글)에 답하며 AI 제안을 쇼핑몰에서 확인해 고른다 → 보내기 전 확인 → ⑥ 후보·구매 링크·핵심 정리 보내기 → 결과함에 저장.
- 플로우 C, 이용자: 나중에 앱을 열어 결과를 듣고 구매 링크를 연다.
- 성공 지표: 봉사자가 요청을 고른 뒤 10분 안에 결과를 보낸다.

**핵심 결정 5가지**
1. **서버는 하나(Next.js)다. FastAPI는 쓰지 않는다.** 파이썬 서버를 붙여도 한 번에 받는 크기와 실행 시간 한도가 같아 얻는 것이 없고, 두 언어를 관리하는 부담만 는다. 시연 뒤 다시 볼 조건은 검증 보고서에 있다.
2. **데이터는 Supabase(서울) 표 두 개뿐이다.** 대기열(`requests`)과 결과함(`results`). 두 봉사자가 같은 요청을 동시에 눌러도 데이터베이스가 먼저 누른 한 명만 받아 준다.
3. **사진과 상세페이지 내용은 서버에 남기지 않는다.** 상세페이지를 보관하면 법적 위험이 있다. 작업 중 값(답, 작은 사진 미리보기)은 봉사자 기기에만 있고, 결과함에는 봉사자가 확인한 것만 남는다.
4. **AI 제안은 봉사자가 반드시 확인한다.** AI가 이미지에 없는 말을 덧붙이는 것을 실험에서 봤다. AI가 낸 후보·링크·사진 설명은 "확인 필요"로 보이고, 핵심 정리 초안은 보내기 전 확인에서 봉사자가 읽고 고친다. 봉사자가 고르거나 확인한 것만 결과에 들어간다. 출처 주소가 없는 후보와 가격·재고·할인 표현은 서버가 거른다.
5. **데모 단계마다 단계 브랜치(작업 갈래) `stage/demo<N>` 하나를 두고, 기능은 그 아래 `feat/demo<N>/<기능>`에서 만든다.** 순서는 플로우 A → ② 봉사자 대기열 → ⑥ 전송이다. v2에서는 ③과 ④를 따로 병렬로 만들 계획이었고, v2.1에서 ③④⑤를 `feat/demo5/research-chat` 하나로 합쳤다.

**쓰는 AI** (모두 OpenAI `gpt-6-luna`. 2026-11-12에 Groq에서 바꿈. 2026-11-13 로컬 실호출로 동작 확인, 공개 주소 응답 시간은 배포 뒤 실측)
- 리서치 챗: 기종 후보·혜택·참고 글은 웹 검색으로 찾고 출처 주소가 있어야 보인다. 질문 문장·핵심 정리 초안, 사진 설명 초안도 만든다. 카드 순서와 필수 여부는 코드가 정하고 AI는 바꾸지 못한다. AI가 실패해도 기본 질문과 쇼핑몰 바로가기로 진행한다.
- 시연 이어 보기 화면의 챗봇: 답에 검색어·확인할 조건·찾는 순서가 꼭 들어가고, 가격·재고·모델명은 금지한다. 예산은 "있음/없음"만 알려 준다(금액을 말하게 하지 않으려고).
- v2의 이미지 글자 읽기(OpenAI 또는 Upstage)와 생김새 설명(Groq qwen)은 v2.1에서 없앴다.

**돈과 한도**: 고정비 0원(Vercel·Supabase 무료). 사진은 브라우저에서 1.5MB 이하로 줄여 보낸다. 챗봇과 리서치 AI는 같은 OpenAI 키와 크레딧을 쓴다. 리서치 AI는 봉사자별로 분당 30회(웹 검색은 8회)까지다. 웹 검색은 1회 약 0.01달러(약 14원, 추정)이고, 요청 1건에 검색 4번이면 약 0.04달러에 토큰 값이 더 든다(배포 뒤 실측). 전체 예산은 5만 원.

**사람이 정하거나 할 일**
- 서버 지역을 서울로 옮길지: 지연을 재 본 뒤 결정
- 개발용 데이터베이스를 따로 둘지(지금은 운영·시험이 한 곳을 같이 씀)
- 결과 보관 기간(추천 7일), 구매 링크 도메인 제한 여부, 결과에 가격 칸을 둘지
- 키 등록(OpenAI. Upstage는 v2.1부터 쓰지 않음), 데이터베이스 표 변경의 원격 적용 승인
- 글자 읽기를 없앤 뒤 남은 점검 표시(`/api/health`의 `extractEngine`)를 정리할지
- 시연 전날 실제 데이터베이스로 리허설(무료 프로젝트는 1주 안 쓰면 멈춘다)

**아직 모르는 것(주요)**: 공개 주소에서의 AI 응답 시간(로컬 실호출에서는 `gpt-6-luna`가 웹 검색 도구를 받았고 검색 5~16초, 그 밖 2~4초였다), 실제 아이폰·VoiceOver에서 리서치 챗이 잘 읽히고 쓰이는지, 동시 선택 SQL이 실제로 한 명만 통과시키는지, 서울로 옮겼을 때 AI 호출이 느려지는지.
