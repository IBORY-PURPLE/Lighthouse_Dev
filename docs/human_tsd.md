# LightHouse 기술 설계 1쪽 요약 (사람용)

기준: `docs/TSD.md` v2(2026-11-09 승인). 상세와 근거는 TSD 본문과 `docs/plans/2026-11-09-overnight/tsd-review.md`. TSD가 바뀌면 이 문서도 같이 고친다.

**무엇을 만드나**: 시각장애인이 음성으로 상품을 요청하면, 봉사자가 AI 조언을 받아 쇼핑몰에서 직접 찾아 결과를 보내는 모바일 웹. AI는 봉사자를 돕기만 하고, 서버와 AI는 쇼핑몰에 접속하지 않는다. 11/24 중간 시연이 목표다.

**흐름** (이용자와 봉사자는 실시간으로 대화하지 않고, 대기열과 결과함을 거쳐 만난다)
- 플로우 A, 이용자: 질문 3개(제품, 예산, 새 제품·중고)에 답 → "봉사자 매칭 요청" → 대기번호를 듣는다. 앱을 다시 열면 대기번호를 다시 듣는다.
- 플로우 B, 봉사자: 대기열에서 요청 선택(먼저 고른 한 명만 성공) → ③ AI에게 찾는 방법 묻기 → 쇼핑몰에서 직접 탐색 → ④ 상세 이미지 캡처를 올려 AI 요약 초안 받기 → ⑤ 요약 확인·수정 → ⑥ 후보·구매 링크·가이드 보내기 → 결과함에 저장.
- 플로우 C, 이용자: 나중에 앱을 열어 결과를 듣고 구매 링크를 연다.
- 성공 지표: 봉사자가 요청을 고른 뒤 10분 안에 결과를 보낸다.
- 로그인: 봉사자만 전화번호·비밀번호로 로그인한다(지금 계정 1개, Vercel 환경 변수). 이용자 화면은 로그인과 접근 코드 없이 열린다.

**핵심 결정 5가지**
1. **서버는 하나(Next.js)다. FastAPI는 쓰지 않는다.** 파이썬 서버를 붙여도 한 번에 받는 크기와 실행 시간 한도가 같아 얻는 것이 없고, 두 언어를 관리하는 부담만 는다. 시연 뒤 다시 볼 조건은 검증 보고서에 있다.
2. **데이터는 Supabase(서울) 표 두 개뿐이다.** 대기열(`requests`)과 결과함(`results`). 두 봉사자가 같은 요청을 동시에 눌러도 데이터베이스가 먼저 누른 한 명만 받아 준다.
3. **이미지와 읽은 글자는 서버에 남기지 않는다.** 상세페이지를 보관하면 법적 위험이 있다. 작업 중 값은 봉사자 브라우저에만 있고, 결과함에는 봉사자가 확정한 요약만 남는다.
4. **AI가 만든 요약은 봉사자가 반드시 확인한다(⑤).** AI가 이미지에 없는 말을 덧붙이는 것을 실험에서 봤다. 근거 문장이 원문에 없으면 "확인 안 됨"으로 표시하고, 가격·재고·할인은 초안에 넣지 않는다.
5. **데모 단계마다 단계 브랜치(작업 갈래) `stage/demo<N>` 하나를 두고, 기능은 그 아래 `feat/demo<N>/<기능>`에서 만든다.** 순서는 플로우 A → ② 봉사자 대기열 → ⑥ 전송이고, ③과 ④는 따로 병렬로 만든다.

**쓰는 AI**
- ③ 찾는 방법 안내: Groq `gpt-oss-120b`(무료). 답에는 검색어·확인할 조건·찾는 순서가 꼭 들어가고, 가격·재고·모델명은 금지한다. 예산은 "있음/없음"만 알려 준다(금액을 말하게 하지 않으려고).
- ④ 이미지 글자 읽기: OpenAI(보유 크레딧) 또는 Upstage. 정답 메모 3~5개로 재 보고 고른다. 상품 1개에 약 14~23원(추정).
- ④ 생김새 설명: Groq qwen. 원문과 대조할 수 없어 뒤로 미룬다.

**돈과 한도**: 고정비 0원(Vercel·Supabase 무료). 한 번에 보내는 크기는 4.5MB까지라 긴 캡처는 브라우저에서 잘라 보낸다. Groq 무료 분당 한도를 ③과 ④가 나눠 쓴다. 전체 예산은 5만 원.

**사람이 정하거나 할 일**
- 서버 지역을 서울로 옮길지: 지연을 재 본 뒤 결정
- 개발용 데이터베이스를 따로 둘지(지금은 운영·시험이 한 곳을 같이 씀)
- 결과 보관 기간(추천 7일), 구매 링크 도메인 제한 여부, 결과에 가격 칸을 둘지
- 키 등록(OpenAI, 선택으로 Upstage), 봉사자 계정 값(번호·비밀번호) 등록, 데이터베이스 표 변경의 원격 적용 승인
- 시연 전날 실제 데이터베이스로 리허설(무료 프로젝트는 1주 안 쓰면 멈춘다)

**아직 모르는 것(주요)**: 한국어 상세 이미지를 어느 엔진이 잘 읽는지, 아이폰에서 긴 캡처 자르기가 되는지, 동시 선택 SQL이 실제로 한 명만 통과시키는지, 서울로 옮겼을 때 AI 호출이 느려지는지.
