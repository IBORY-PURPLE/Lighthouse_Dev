# LightHouse 아이폰 기준 개발 계획
작성일: 2026-11-03, 수정일: 2026-11-04

**목표**: 쇼핑몰 직접 검색의 부담을 덜도록, 전맹·저시력 시각장애인이 아이폰 화면낭독기(VoiceOver)를 켠 채 음성으로 상품을 요청하고, 봉사자가 AI 조언을 받아 찾아 확인한 답변을 들은 뒤 구매 링크까지 여는 흐름을 실제 서버와 실제 폰에서 증명한다.

**결과물**
- 공개 주소의 모바일 웹 서비스, 전체 흐름 시연 영상, 정확도 결과표, AI 보조 효과 측정 결과, 법적 체크리스트, 다음 멘토링용 작은 시연(상품 페이지 캡처 → 이미지 속 글자 읽기(OCR) → AI 요약).
- 제품·기술 문서(PRD·TSD)와 새 비공개 저장소(Lighthouse_Dev). Claude가 구현하고 Codex가 검증하는 규칙을 담고 자동 검사로 강제한다.

**방법**
1. 기반 (AI, 11/3~5 추정): 문서, 프로젝트 구조, 공용 에이전트 규칙, 자동 검사, 앱을 띄워 스크린샷을 남기는 도구, 시제품 이전.
2. 존폐 시험과 법적 확인 (사람 시간 다시 계산, AI가 도구 준비, 11/7까지): VoiceOver를 켠 아이폰에서 브라우저 음성 인식(음성을 글자로 바꾸는 기능, STT)을 시험하고, 실패하면 iOS 키보드 받아쓰기로 바꾼다. 듣기 버튼 겹침, 답변을 기다리는 동안의 화면 잠금, 실제 상세 이미지 요약(멘토링 시연 겸용), 쿠팡 구매 흐름 기록도 본다. 법적 체크리스트는 박재민(동의 후 확정). 11/8에 입력 방식과 첫 상품군을 정한다.
3. 핵심 흐름 (AI, 11/5~15 추정, 다시 계산): 미리 넣은 데이터로 음성 요청, 봉사자 화면, 캡처 올리기, 답변 전달, 저장·재사용을 먼저 만든다. 그 뒤 AI를 상세 이미지 요약, 답변 설명문 초안, 혜택·할인 정리 순서로 붙이고 정확도를 잰다. 유료 실행은 승인 후 한다.
4. 배포와 마무리 (AI, 사람은 호스팅 결제와 실기기 확인, 11/22까지): 공개 주소에 올리고, 11/16~22는 개발 마무리와 팀 내부 시험에 쓴다. 데모는 11/23 완성.
5. QA와 발표 (전원, 11/23~29): 11/23~27 링키지랩 사용자 테스트(QA, 송채우가 직접 문의). 이후 수정, 영상 촬영, 발표 준비.

**범위**
- 하는 것(흐름): 이용자가 음성으로 요청하면 봉사자(이번엔 팀원 대역)가 쿠팡이든 편한 사이트든 직접 찾아 캡처를 올린다. AI는 조언만 한다(검색어·조건 제안, 요청에 맞는지 확인, 요약, 설명문 초안, 혜택 정리). 봉사자가 확인해 후보 1개, 구매 링크, 구매 가이드를 보낸다. 가이드는 쿠팡만 버튼 이름·순서까지, 다른 사이트는 옵션·가격·쿠폰 안내만. 화면을 열어 두면 진행 상황과 답변 도착을 VoiceOver로 알린다. 답변은 화면 글자로 보여 VoiceOver가 읽게 하고, 원하면 듣기 버튼으로 글자를 소리로 읽어 준다(TTS, 브라우저 기본 기능).
- 하는 것(저장·재사용): 주소·가격·혜택 같은 사실, AI 요약, 봉사자 설명 글만 저장한다. 같은 주소나 비슷한 요청이 오면 AI가 이전 설명을 봉사자에게 먼저 보이고, 봉사자가 가격·혜택을 확인해 보낸다. 법적 확인 전에는 시연용이고 공개하지 않는다.
- 하지 않는 것: 실시간 통화와 통화 내용 저장(QA 피드백 후 재판단), 외부 봉사자 섭외, 서버·AI의 쇼핑몰 직접 접속과 탐색, 차단 우회, 원본 상세페이지·개인정보 저장, 결제 어려움 해결(원터치 결제 저장을 가정), 자동 결제, 계정 대행, 구매·건강 판단, 안드로이드 검증, 계정, 1365 연동, 모니터링.

**정해 줄 것** (답이 없으면 추천안으로 간다. 팀원 담당은 본인 동의 후 확정)
1. 서버 위치: 저가 호스팅과 저장 디스크(월 1~2만 원 추정) / 집 PC를 터널로 공개(무료지만 PC를 켜 둬야 하고 무료판은 경고 화면과 월 1GB 제한). **추천: 저가 호스팅.** QA 중 서버가 꺼지면 안 된다.
2. 정답지 10~20개 담당: 최은찬 / 송채우 / 분담. 상품당 30분, 전체 5~10시간 추정. **추천: 최은찬, 11/11까지.** AI를 만드는 사람과 채점 기준을 만드는 사람을 나눈다.
3. 기존 Dev 폴더와 초안 PR(코드 변경 제안) 3개: 옮긴 뒤 닫고 이동 안내만 남김 / 그대로 둠. **추천: 옮긴 뒤 닫기.** 기준 코드를 한 곳에 모은다. 커밋하지 않은 변경 51건은 건드리지 않는다.
4. QA 기간 봉사자 대역 대기: 전원 교대 / 1명 고정. **추천: 전원 교대.** 외부 봉사자가 없어 10분 응답 목표를 팀이 지켜야 하고, 닷새를 한 사람이 맡기는 어렵다. 시간표는 링키지랩 일정이 나오면 맞춘다.

**비용** (모두 추정)
- 시간: 재추정 필요. 이전 추정은 송채우 약 20시간, 다른 팀원 합쳐 20~30시간(영상·발표 준비 제외), AI 11/3~15 사이 약 8~10일. 다시 잴 때 매일 14:00 산출물 공유와 주 1회 온라인 미팅을 넣는다.
- 돈: 상한 5만 원(약 35달러) 유지. 서버 월 1~2만 원. 정확도 실험의 이전 추정 1.5~2.4만 원은 합성 이미지 단가 기준이라, 실제 이미지로 단가를 재서 다시 계산한다. 남는 돈은 테스트 때 분석에 쓴다(금액 다시 계산). 사례비·QA 비용은 상한 밖이고 금액 미정.

**성공 기준**
- 전체 흐름: 음성 요청 → 봉사자 찾기·캡처 → AI 보조 → 봉사자 확인 → 답변 듣기 → 구매 링크 열기 → 다음 요청 때 이전 설명 제시를 실서버·실기기에서 1회 이상 성공하고 영상으로 남긴다. 봉사자는 팀원 대역임을 밝힌다.
- AI 품질: 실제 상품 10~20개 정답지(쿠팡 위주, 네이버쇼핑·11번가 일부) 기준 핵심 항목 정확도 90% 이상, 지어낸 정보 0건. 못 미치면 모델을 바꾸거나 상품군을 줄인다. AI 보조 있을 때와 없을 때 봉사자 소요 시간은 비교해 측정한다.
- 속도: 첫 진행 안내 5초, 답변 10분 이내(시험 시간대 봉사자 대기). 저장된 결과 3초, 상품 전체 요약 2분 같은 이전 수치는 실측 후 조정한다.
- 개발 완료: 검사 통과, 앱 구동 기록과 화면 스크린샷, Codex 독립 검증. VoiceOver는 사람이 판정하고, 음성 버튼 찾기·실행·인식 결과 확인·수정은 팀이 화면을 가리고 수시로 점검한다. 링키지랩 QA는 합격 조건이 아니라 측정이다.

**위험**
1. 법적: 멘토는 상세페이지 정보 보유 자체가 재산권 문제이고 상용화에 법적 위험이 있다고 했다. 쿠팡 약관은 승인 없는 자동화 접속을 금지한다. 사람이 캡처하는 방식이 괜찮은지는 아직 모르고, 시험 통과가 허용을 뜻하지 않으며, 우회는 하지 않는다. 위험하면 저장·재사용은 비공개 시연으로만 쓰고 상용화 전 플랫폼 협의 필요를 문서화한다.
2. QA 단일 경로: 당사자 테스트 경로는 링키지랩 하나다. 11/23 시작은 가정이고, 복지관 6곳은 전화 접촉했으나 방문 일정이 없다.
3. 미검증 가정: VoiceOver와 음성 인식 동시 사용, 답변을 기다리는 동안 화면이 잠겨도 알림이 오는지, 쿠팡 구매 화면 틀이 상품 간 같다는 것(상품 여러 개로 확인), 당사자가 실제로 검색에 어려움을 겪는다는 것(QA 때 확인, 틀리면 발표에 그대로 밝힌다).
