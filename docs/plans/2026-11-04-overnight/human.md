- 다음 작업: 다른 기기(PC 봉사자 화면)로 요청을 넘기는 외부 저장소. 서버 함수에서 접속하는 단순한 키-값 저장소(Upstash Redis 무료 등)로, 요청 저장·조회, 상태 변경(대기→매칭→답변 완료), 봉사자 화면의 주기적 새 요청 조회, 자동 만료 삭제, 서버 재시작에도 유지되는 횟수 제한이 필요하다. 개인정보는 넣지 않는다.

1. 실기기: 아이폰 크롬의 음성 인식은 안 될 수 있다(실패 보고가 있으나 오래된 자료라 현재 상태 미확인, 사파리는 부분 지원). 0번 블록은 마이크 허용과 한 문장 인식만 보므로, 전체 흐름에서 VoiceOver 음성과 충돌하는지는 아침이 첫 시험이다. 대체 경로는 입력창에 iOS 키보드 받아쓰기, 또는 같은 주소를 사파리로 열기다. 사파리로 옮기면 봉사자 화면도 사파리에서 연다.
2. 무인 '모든 권한 허용': 사람이 없어 실수를 바로 막지 못한다. 안전 훅(위험한 명령을 실행 전에 막는 장치)이 `main` 직접 커밋·푸시, 강제 푸시, origin(Cursor 쪽 저장소) 푸시, `.env` 접근, 위험한 삭제 대부분을 막지만, 패턴 기반이라 전부 막지는 못한다. 조건을 만족한 PR의 AI 병합은 허용된다. GitHub에는 `main` 보호 규칙이 없다(확인됨). 결제, 외부 발송, 저장소 밖 변경, 지정 프로젝트 밖 배포도 규칙으로 금지한다. 훅에 막히면 우회하지 않고 기록한다.
3. 한도·Bugbot·공개 주소: Ultra는 5시간 한도가 없고 주간 한도는 현재 26% 사용, 11/9 오전 10시 초기화다. 추가 사용량이 꺼져 있어 한도에 닿으면 추가 요금 없이 멈춘다. 11/9 전까지 5일 밤을 돌리고 낮에도 쓰므로 하룻밤 사용을 주간 한도의 12% 이내로 유지한다. 6,500만 토큰이 그 안에 드는지는 모르니 1블록 사용량을 재서 다음 블록 크기를 조정하고, 넘으면 최소 합격 경로만 남긴다. Bugbot은 PR #2에서 실행이 시작됐지만 결과는 아직 확인 전이고, 결과가 오지 않으면 모든 PR이 보류로 끝난다. 쌓인 PR에서 Bugbot이 도는지는 문서에 없어 미확인이고, 안 돌면 해당 PR은 보류다. 공개 주소가 남용되면 돈은 나가지 않지만 Groq 일일 한도가 소진되어 아침 시연이 막힌다. 4블록의 보호 장치로 막되, 서버 메모리에 세는 횟수 제한은 서버가 재시작되거나 여러 대로 나뉘면 초기화되어 완화 수단일 뿐이다.
