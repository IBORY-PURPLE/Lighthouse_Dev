# 이용자 요청을 봉사자에게 먼저 보여 주기 — 1쪽 요약 (2026-11-18)

**확인 결과: 실험에서 4번 넘게 답한 내용은 서버에 저장되지 않았습니다.** DB에 남은 것은 AI가 뽑은 "소니 무선 헤드셋 · 십만 원 정도 · 새/중고 정하지 않음"과 브랜드(Sony)·품목(헤드셋)뿐입니다. 질문과 답은 매 턴 AI에 보냈다가(OpenAI 기록 끔) 버리고, 이용자가 확인한 요약 한 줄만 이용자 휴대폰에 남습니다.

**목표**: 봉사자가 요청을 맡으면 리서치 전에 이용자가 말한 요청·조건·질문에 대한 답을 차례로 확인하고 시작하게 한다.

**결과물**
- 접수할 때 이용자가 확인한 요약과 질문·답을 함께 저장(이용자 화면 코드는 안 바꿈)
- 봉사자 챗: [구매했어요]나 [리서치만]을 누르면 기종 질문 전에 "이용자 요청" 카드가 한 장씩 나오고, [다음]으로 다 본 뒤 기종 질문이 나옴
- 리뷰 문단을 만드는 AI가 이용자 조건을 참고(지어내지 않게 하는 검사는 그대로)
- 시험·문서·DB 변경 파일(원격 DB 적용은 승인 뒤)

**방법**
1. 음성 대화 기록에서 질문·답을 뽑아 접수에 함께 실음 — AI, 1시간
2. 새 표에 저장하고 맡은 봉사자에게만 보여 줌, 리뷰를 보내면 지움 — AI, 2시간
3. 봉사자 챗 카드 넘기기 화면, 리뷰 AI 반영, 시험 — AI, 3시간
4. 로컬 화면 확인 → 승인 → DB 적용·PR·Codex 검증·병합 — 사람 15분, AI 1시간
5. 휴대폰으로 말하고 노트북에서 맡아 카드 확인 — 사람 10분

**범위**
- 하는 것: 위 결과물. 구매함·리서치만 두 경우 모두
- 하지 않는 것: 대기열 카드에 답 보이기(맡기 전 다른 봉사자에게 이용자 말이 퍼지지 않게), 지난 요청의 답 되살리기(저장된 적이 없어 불가), 음성 AI 지시문 수정, AI가 답을 다시 요약하기

**정해 줄 것**
1. 무엇을 저장? **A. 이용자가 확인한 요약 + 질문·답 원문(추천: 이용자 말 그대로라 지어낼 틈이 없음)** / B. 요약만 / C. 원문 + AI 항목 정리(호출 비용, 지어낼 위험)
2. 얼마나 보관? **A. 리뷰를 보내거나 요청이 만료되면 바로 지움(추천: 그 뒤엔 쓸 곳이 없음)** / B. 요청과 함께(완료 7일 뒤 삭제)
3. 리서치 AI에도 넘길까? **A. 리뷰 문단 AI에만 넘기고, 그 호출은 OpenAI 기록을 끔(추천)** / B. 대화 질문 AI까지 넘기고 둘 다 기록 끔(대시보드에서 대화 턴 기록이 거의 사라짐) / C. 넘기지 않음
4. "궁금한 점"을 따로 물을까? **A. 이번엔 그대로, 답에 나온 것만 보여 줌(추천: 동료 원본 지시문 유지)** / B. 음성 AI가 등록 확인 전에 한 번 더 묻게(동료 동의 뒤 별도 PR)

**비용**: 사람 약 30분, AI 약 7시간, 돈 0원(시험은 가짜 AI, 운영 AI 호출 횟수는 그대로)

**성공 기준**
- 음성으로 답한 요청을 맡고 [구매했어요]를 누르면 요약과 질문·답 카드가 차례로 나오고, 다 본 뒤 기종 질문이 나온다
- 대기열, 다른 봉사자, 이용자 상태 조회, 로그에는 답이 나오지 않는다. 리뷰를 보내면 DB에서 지워진다
- `npm run check`, 화면 시험, Codex 검증 통과

**위험**
- 이용자가 개인정보를 말하면 그대로 저장됨 → 전화번호 모양은 가림, 맡은 봉사자 1명만 봄, 리뷰 뒤 삭제
- 기존 화면 시험 8곳에 "카드 넘기기" 한 단계를 더해야 함(기준을 낮추는 것은 아님)
- DB 적용 전에 배포되면 카드에 요약·답 없이 기본 정보만 나옴(오류는 나지 않음)
