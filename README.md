# LightHouse

쇼핑앱을 혼자 쓰기 어려운 시각장애인을, 음성 대화 AI와 봉사자용 AI 리서치 챗으로 그 물건을 직접 써 본 사람의 리뷰와 이어 주어, 듣고 고를 수 있게 돕는 모바일 웹 서비스입니다.

> 현재 개발 중인 아이폰(VoiceOver) 기준 MVP입니다. 상용 서비스가 아니며, 공개 전 법적 확인이 필요합니다.

## 어떤 문제를 푸나요

- 상품 상세 정보의 상당 부분이 이미지라 화면낭독기(VoiceOver)가 읽어 주지 못합니다.
- 검색, 비교, 옵션 선택을 화면 소리를 들으며 한 단계씩 따라가야 해 오래 걸립니다.
- 리뷰는 많아도 누가 실제로 써 봤는지, 어떤 말을 믿어야 할지 가리기 어렵습니다.

LightHouse는 이 과정을 "말로 요청하고, 써 본 사람이 답하고, 귀로 듣고 고르는" 방식으로 바꿉니다.

## 누가 쓰나요

| 사람 | 기기 | 하는 일 |
|---|---|---|
| 이용자 | 휴대폰 | 아이폰 VoiceOver를 쓰는 전맹·저시력 시각장애인. 앱 설치 없이 링크로 열고 홈 화면에 추가해 씁니다 |
| 봉사자 | 노트북 | 요청한 물건을 사 봤거나 대신 조사해 줄 자원봉사자. 이번 MVP에서는 팀원이 대신하며, 시연 때 이를 밝힙니다 |

## 이렇게 동작합니다

1. **말로 요청(이용자)**: 음성 AI가 무엇을 사고 싶은지, 예산, 새 제품·중고 여부를 차례로 묻고, 요약을 확인받아 봉사자 대기열에 접수합니다. 대기·진행·완료 상태는 언제든 다시 들을 수 있습니다.
2. **요청 맡기(봉사자)**: 노트북 챗봇 화면에서 대기열의 요청을 맡고, 이용자가 말한 조건을 카드로 먼저 확인합니다.
3. **리서치 챗(봉사자 + AI)**: AI가 한 번에 하나씩 묻습니다. 산 기종(사지 않았으면 "리서치만"), 장점, 사용 사진, 같이 고민한 제품과 이유, 혜택, 참고 글 순서입니다. AI는 웹 검색으로 기종 후보·대안·혜택 링크를 건네고, 올린 사진이 실제 사용 사진인지 확인합니다.
4. **리뷰 확정과 보내기(봉사자)**: AI가 모은 답으로 한 문단 리뷰 초안을 쓰고, 봉사자가 읽고 고쳐 확정한 뒤 보냅니다.
5. **듣고 고르기(이용자)**: 휴대폰에 "리뷰가 도착했어요" 알림이 옵니다. VoiceOver로 리뷰를 듣고, 봉사자가 확인한 링크를 엽니다.

리뷰에는 "구매 인증됨"(사용 사진으로 인증) 또는 "리서치만" 표시가 붙습니다. 실제로 써 본 사람의 추천일수록 더 믿는다는 가설을 사용자 테스트로 확인합니다.

## 원칙

- AI는 봉사자의 어시스턴트입니다. 질문 순서, 후보, 리뷰 초안까지만 만들고, 보낼 내용은 봉사자가 확정합니다.
- AI는 열리는 웹 페이지(블로그, 공식 페이지 등)만 검색합니다. 쇼핑몰 로그인, 결제, 계정 대행은 하지 않습니다. 접근이 막힌 쇼핑몰은 봉사자가 직접 확인합니다.
- 가격·재고·할인 숫자와 없는 모델명을 지어내 리뷰에 넣지 않습니다. 구매 판단은 이용자가 합니다.
- 상세페이지 원본과 사진 원본을 저장하지 않습니다. 리서치 대화와 사진은 리뷰를 보내면 지우고, 보낸 결과는 완료 7일 뒤 지웁니다.
- 이용자가 말한 질문과 답은 요청을 맡은 봉사자에게만 보이고, 리뷰를 보내거나 요청이 만료되면 지웁니다.

## 성공 기준

- 실제 서버와 실제 아이폰에서 음성 요청부터 리뷰 듣기, 링크 열기까지 1회 이상 성공하고 영상으로 남깁니다.
- AI 출력과 보낸 리뷰에 가격·재고·할인 숫자와 없는 기종명이 0건입니다.
- 리서치는 품질이 우선입니다. 요청을 끝내는 시간 제한은 두지 않습니다.

## 기술 구성

| 부분 | 쓰는 것 |
|---|---|
| 이용자 화면 | 모바일 웹(홈 화면 설치형), 브라우저 음성 인식·음성 합성, VoiceOver 접근성, 웹 푸시 알림 |
| AI | OpenAI 언어 모델: 이용자 음성 대화, 봉사자 질문 진행, 웹 검색, 사용 사진 확인, 리뷰 초안 |
| 서버·데이터 | Next.js(Vercel), Supabase(서울). 요청당·하루 AI 사용 상한 |
