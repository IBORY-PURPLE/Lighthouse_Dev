# 성공 기준: 무엇을 '완료'로 인정하나

기능 하나는 PR 하나다. 아래가 모두 있어야 `완료`로 기록한다.

## 완료 조건

1. 검사·시험 명령을 실제로 돌렸고, 그 출력의 요약(명령, 통과 수, 종료 코드)이 PR 본문에 있다.
   - 이유: 돌렸다는 말만으로는 아침에 확인할 수 없다. 어기면: 안 돌린 시험이 통과로 보고된다.
2. 화면을 바꿨으면 스크린샷 링크가 PR 본문에 있다(`pr-flow.md`의 증거 위치).
   - 이유: 시험은 화면 깨짐을 놓친다. 어기면: 깨진 화면을 아침 시연에서 처음 본다.
3. Codex 판정이 `통과`이고 PR 본문에 있다(`pr-flow.md`의 판정 기준).
   - 이유: 만든 쪽이 스스로 합격시키지 않는다. 어기면: 같은 맹점이 그대로 올라간다.
4. Cursor Bugbot 결과가 나왔고 심각한 지적이 0건이며 PR 본문에 있다(`pr-flow.md`의 판정 기준).
   - 이유: Codex는 기능을, Bugbot은 코드를 본다. 어기면: 작동은 하지만 결함이 있는 코드가 올라간다.

하나라도 없으면 `미완료`다. PR을 열어 둔 채 빠진 것을 진행 기록에 적는다.

## 사람 판정 항목

- VoiceOver, 실제 아이폰, 음성 인식 실동작은 AI가 판정하지 못한다. `사람 판정 대기`로 적고 완료 조건에 넣지 않는다.
  - 이유: 밤사이 실기기가 없다. 어기면: 가짜 음성 입력 통과가 실기기 통과로 읽힌다.
- 가짜 입력으로 통과한 시험은 보고에 `가짜 음성 입력 기준`이라고 밝힌다.
  - 이유: 합격 수준을 정확히 전하기 위해서다. 어기면: 아침 시연 결과와 보고가 어긋난다.

## 실패 세기

아래 실패가 PR 작업 중 한 번이라도 나면 그 PR은 `실패 이력 있음`이다. 고쳐서 통과해도 지워지지 않는다.

- 세는 것: 검사, 시험, 빌드, 배포 실패, Codex 심각한 지적, Bugbot 심각한 지적. PR 열기 전 개발 중 실패도 포함한다.
- 세지 않는 것: 새 시험을 먼저 쓰고 구현 전에 일부러 틀리는지 확인한 첫 1회. 진행 기록에 `의도된 실패`로 적는다.
- 실패할 때마다 진행 기록에 명령과 오류 한 줄을 적고, PR 본문에 실패 횟수를 적는다.
  - 이유: AI 병합 여부가 이 기록으로 갈린다. 어기면: 실패한 PR이 사람 확인 없이 main에 들어간다.
- 이 기록은 AI의 자기 신고라 훅으로 강제하지 못한다. 실패를 숨기는 것은 가장 무거운 위반이다.

## 시험을 고칠 때

- 통과시키려고 시험을 빼거나 기준을 낮추지 않는다. 시험이 틀렸다면 이유를 PR 본문에 적고, Codex가 그 변경을 보게 한다.
  - 이유: 합격 기준이 밤사이 조용히 내려가면 안 된다. 어기면: 전부 통과인데 기능은 안 되는 아침을 맞는다.

## 막혔을 때

- 같은 실패(같은 명령, 같은 오류)가 3회 나거나 블록 끝 시각이 지나면 멈춘다.
  - 이유: 같은 시도를 반복하면 토큰만 쓴다. 어기면: 한 문제에 밤을 다 쓰고 뒤 블록이 비어 버린다.
- 멈출 때 원인, 시도한 방법, 다음에 할 일을 진행 기록에 적고 `미완료`로 둔 채 다음 블록으로 간다.
  - 이유: 다음 세션은 기록만 보고 이어 간다. 어기면: 같은 시도를 처음부터 되풀이한다.
