# 핵심 정리·점검 보고는 HTML 링크로

사람에게 핵심 정리, 점검 결과, 막힌 곳 요약을 알릴 때는 HTML 한 장으로 만들어 localhost 링크를 준다. 채팅에는 링크와 한 줄 요약만 쓴다.

- 이유: 채팅 글은 길면 읽기 어렵다(2026-11-10 이용자 요청). 어기면: 핵심이 긴 글에 묻혀 판단이 늦어진다.
- 이 규칙은 보고·점검용이다. 계획의 `human.md`/`ai.md` 규칙(`planning-flow.md`)은 그대로 따른다.

## 만드는 법

- 저장: `docs/briefings/<YYYY-MM-DD>-<짧은-영문-이름>.html`. 지난 정리는 지우지 않고 날짜별로 둔다. git에는 올리지 않는다(`.gitignore`).
  - 이유: 임시 보고서가 PR을 어지럽히지 않게 한다. 어기면: 보고 파일이 커밋에 섞인다.
- 서버: `python -m http.server 8765 --directory docs/briefings`를 백그라운드로 띄운다. 이미 8765에서 돌고 있으면 새로 띄우지 않고 링크만 준다.
- 링크: `http://localhost:8765/<파일명>`을 답변 맨 위에 둔다. 링크를 주기 전에 `curl -sI`로 200을 확인한다.
  - 이유: 안 열리는 링크를 주면 신뢰가 깨진다. 어기면: 열리지 않는 주소를 받는다.

## 페이지 형식

한 줄 요약 → 상태 표 → 막힌 곳 → 진행 순서 → 정해 줄 것(추천 표시) → 비용·끝 기준·위험 순서로 쓴다. 큰 글씨, 표, 여백을 쓰고 기술 용어는 풀어 쓴다. 휴대폰 폭과 다크 모드에서도 읽혀야 한다. 외부 파일·스크립트를 불러오지 않는 단일 HTML로 만든다.
