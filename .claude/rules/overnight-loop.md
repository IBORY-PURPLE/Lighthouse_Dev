# 밤샘 개발 루프

매일 밤 AI가 무인으로 개발한다. 사람은 아침에 결과를 판단한다.

## 세션

- 기능 하나 = 세션 하나 = PR 하나. 통합, 버퍼, 마무리 블록도 각각 새 세션이다.
  - 이유: 이전 기능의 대화가 다음 기능의 호출마다 비용으로 붙지 않는다. 어기면: 밤 후반에 호출당 비용이 몇 배가 된다.
- 세션을 끝낼 때 `progress.md`에 항목을 하나 추가한다. 다음 세션은 이것만 보고 이어 간다.
  - 이유: 다음 세션은 지난 대화를 모른다. 어기면: 같은 결정을 다시 하거나 뒤집는다.

## 진행 기록 형식

오늘 계획 폴더의 `progress.md`에 시간순으로 쌓는다. (전역 `planning-flow.md`는 `ai.md` 안에 진행 기록을 두라고 하지만, 이 프로젝트는 마지막 항목만 읽으려고 파일을 나눈다. 프로젝트 규칙이 우선이다.)

```
## HH:MM 블록 N <기능>
상태: 완료 | 미완료 | 보류
PR: <번호와 링크>, 실패 횟수: N
결정: <다음 세션이 알아야 할 것>
다음 할 일: <한 줄>
토큰: 실제 입력/출력 또는 '미측정', 예상 대비 %
```

## 모델

- 구현과 판단은 Opus 5.5 high, 파일 5개 이상 탐색과 긴 로그는 Sonnet 하위 에이전트.
  - 이유: 판단 품질은 지키고 읽기 비용만 줄인다. 어기면: 사용량 한도에 일찍 닿는다.
- 제품 안 챗봇의 모델과 계획 문서 작성은 각각 그날 계획과 전역 `planning-flow.md`를 따른다.

## 시간과 토큰

- 블록 끝 시각을 넘기면 멈춘다(`success-criteria.md`의 막혔을 때).
- 블록 토큰이 예상의 150%를 넘으면 계획의 포기 순서대로 범위를 줄이고, 기록하고 마무리한다.
  - 이유: 8시 종료와 주간 사용량을 지킨다. 어기면: 뒤 블록을 돌릴 사용량이 남지 않는다.
- 실행 중 토큰을 잴 수 없으면 시간 기준만 적용하고 `미측정`이라 적는다. 숫자를 지어내지 않는다.
  - 이유: 다음 날 추정을 고칠 근거다. 어기면: 틀린 추정이 매일 반복된다.
- 사용량 한도에 걸리면 기록하고 초기화까지 기다린 뒤 다음 블록을 줄인다.

## 금지선

`.claude/hooks/guard.js`가 아래 대부분을 실행 전에 막는다. 패턴 기반이라 전부 막지는 못하므로, 훅이 막지 않아도 규칙은 그대로다.

- main 직접 커밋·푸시, 강제 푸시, 브랜치 삭제 푸시, `origin` 푸시.
- `.env` 읽기·쓰기·커밋, 키 값 출력.
- `git reset --hard`, `git clean -f`, 저장소 밖 파일 변경, 저장소 삭제.
- 결제, 유료 플랜 변경, 메일·메시지 외부 발송, 지정 프로젝트 밖 배포, 돈 상한 초과 호출.
- 이유: 잠든 사이 되돌리기 어려운 일을 막는다. 어기면: 키 유출이나 작업 손실을 아침에야 안다.
- 훅에 막히면 우회하지 말고 이유를 기록하고 다른 방법을 찾거나 멈춘다. 이용자가 그 수정을 명시적으로 허락한 경우 말고는 훅을 고치거나 끄지 않는다. 고친 뒤에는 `node .claude/hooks/guard.test.js`를 통과시킨다.
  - 이유: 우회가 되면 금지선이 아니다. 어기면: 안전장치 전체가 무의미해진다.

## 아침 보고

마지막 블록에서 오늘 계획 폴더의 `morning-report.md`를 쓴다. 사람이 가장 먼저 보는 파일이다.

- 순서: 시연 주소와 배포 커밋, 시연 절차, PR 표(번호, 기능, 판정, 실패 횟수, AI 병합/보류), 사람 판정 항목, 미완료와 막힌 이유, 실제 사용량과 예상 차이.
  - 이유: 보류 PR을 빠르게 판단해야 한다. 어기면: 아침 15분 안에 시연과 판단을 못 끝낸다.
